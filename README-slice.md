# 快手 `.slice` 分片还原说明

> 适用范围：本 README 记录对用户提供的 `mhYSCq8gBh4_ShowHevcFhdL3Mgr.slice` 的实际分析与验证结果。它不是快手官方格式规范，也不保证适用于其他来源或版本的 `.slice` 文件。
>
> 验证日期：2026-11-03。配套工具：同目录下的 `restore_slice.py`。

## 1. 结论

这个文件由一层自定义分片结构包裹 FLV 数据构成。内层视频是标准 HEVC/H.265，音频是 HE-AAC。问题出在外层封装，不需要 KVC 私有解码器、unidbg、安卓手机或 root。

处理链路为：

```text
原始 .slice
  ↓ 按块长度遍历文件
移除各块固定头和可选扩展头
  ↓ 合并 FLV 初始化片段、按原顺序拼接数据
完整 FLV
  ↓ FFmpeg -c copy 转封装
普通 MP4（HEVC + AAC）
```

上述步骤不重新编码音视频。`-c copy` 会更换容器、重写容器信息，但不执行有损画面或音频压缩。

### `.slice`、FLV、HEVC 分别是什么？

| 名称 | 在本样本中的作用 |
|---|---|
| `.slice` | 文件后缀；此样本存放快手自定义分片数据 |
| 自定义分片层 | 将内层媒体字节拆成许多带头信息的块 |
| FLV | 内层媒体容器，按标签组织元数据、音频和视频 |
| HEVC/H.265 | 视频压缩编码 |
| HE-AAC | 音频压缩编码 |
| MP4 | 还原后可选用的输出容器 |

同样的文件后缀不代表相同格式。不要对任意 `.slice` 文件直接应用本规则。

## 3. 与普通 FLV 的区别

普通 FLV 的逻辑结构为：

```text
FLV Header
PreviousTagSize0
Tag Header + Tag Data + PreviousTagSize
Tag Header + Tag Data + PreviousTagSize
...
```

本样本的外层结构为：

```text
Block 0: 固定头 + FLV 初始化片段
Block 1: 固定头 + 另一份 FLV 初始化片段
Block 2: 固定头 + 一段 FLV 数据
Block 3: 固定头 + 一段 FLV 数据
...
Block N: 固定头 + 扩展头 + 一段 FLV 数据
...
```

关键区别是：**一个分片块不等于一个 FLV 标签，也不等于一帧视频。** FLV 标签可能跨越多个分片。必须先移除外层头、拼接所有有效载荷，再按 FLV 标签解析。

因此，下列处理方式不成立：

- 直接将 `.slice` 重命名为 `.flv`。
- 只删除文件开头 15 字节。
- 把每个分片独立交给 FFmpeg 解码。
- 在原始文件中搜索 `09`、`08` 或 `FLV`，据此随意切分数据。

压缩视频本身可能包含相同字节，只有结合长度和边界校验才可靠。

## 4. 外层块结构

以下偏移均相对于当前块开头，均从 0 开始。

### 4.1 固定头

本样本每个块都有 15 字节固定头：

| 偏移 | 长度 | 本次已验证的用途 |
|---|---:|---|
| `0..1` | 2 字节 | 按大端读取；高 12 位表示整个块的字节长度 |
| 字节 1 的低 4 位 | 4 bit | 观察到取值 0、2、3；具体语义未确认 |
| `2..13` | 12 字节 | 未逐字段确认，当前还原过程不需要解释 |
| `14` | 1 字节 | 最低位为 1 时，后面存在扩展头；其余位语义未确认 |

块总长度计算：

```python
word = int.from_bytes(data[pos:pos + 2], "big")
block_size = word >> 4
low_bits = word & 0x0F
next_pos = pos + block_size
```

这里的 `block_size` **包括固定头、扩展头（若有）以及媒体有效载荷**。它不是单独的媒体数据长度。

这条长度规则在本样本中连续遍历了全部 46,310 块，最终位置恰好等于文件长度，没有剩余字节。按照该规则，长度字段可表示到 4095；这只是本次解析方式的字段范围，不应据此推断其他版本的上限。

低 4 位取值统计：

| 值 | 块数 |
|---|---:|
| 0 | 2 |
| 2 | 4,025 |
| 3 | 42,283 |

这些数量提供了进一步研究的线索，但当前脚本不把它们解释成正式的音频、视频或初始化类型枚举。

### 4.2 前三个块实例

| 块索引 | 文件偏移 | 固定头十六进制 | 块总长度 |
|---|---:|---|---:|
| 0 | 0 | `4ba000000000000000010000000000` | 1210 |
| 1 | 1210 | `432000000000000000020000000000` | 1074 |
| 2 | 2284 | `4e5300065f56c60a9cbf0000d7ed50` | 1253 |

例如：

```text
0x4BA0 >> 4 = 0x04BA = 1210
0x4320 >> 4 = 0x0432 = 1074
0x4E53 >> 4 = 0x04E5 = 1253
```

因此第三个块结束于 `2284 + 1253 = 3537`，那里就是下一个块的起点。

### 4.3 可选扩展头

检测条件：

```python
has_extension = bool(data[pos + 14] & 1)
```

当它为真时，固定头之后首先出现 2 字节大端扩展长度：

```text
固定头（15 字节）
扩展长度（2 字节，属于扩展头）
其余扩展内容
媒体有效载荷
```

处理代码：

```python
payload = data[pos + 15:pos + block_size]
if has_extension:
    extension_size = int.from_bytes(payload[:2], "big")
    payload = payload[extension_size:]
```

本样本扩展头全部以 `00 0b` 开始，表示总共跳过 11 字节，**不是 2 + 11 字节**。

其中一个实例：

```text
00 0b 01 00 00 01 a1 9f 8b 2f 9c
```

扩展内容看起来具有固定结构，但本次没有证明其中各字段的确切含义；脚本仅按其长度剥离。不应把某些字节看似时间戳的特征直接视为协议定义。

## 5. 合并 FLV 初始化片段

本样本前两个块的有效载荷均以 `FLV\x01` 开始：

- 第一份初始化片段包含元数据和视频解码配置。
- 第二份包含元数据和音频解码配置。

直接把这两份完整 FLV 头拼在一起，会在标签序列中插入第二个文件头，导致错误解析。

当前规则：

1. 第一份 `FLV Header + PreviousTagSize0` 保留。
2. 后续块若在有效载荷开头再次出现 `FLV\x01`，确认 `DataOffset == 9`。
3. 仅去掉其开头 13 字节：9 字节 FLV Header 加 4 字节 PreviousTagSize0。
4. 后面的元数据和音视频配置标签仍保留。

```python
if payload.startswith(b"FLV\x01") and output:
    assert payload[5:9] == b"\x00\x00\x00\x09"
    payload = payload[13:]
```

脚本只检查**块有效载荷起点**处的重复 FLV 头，不对整个压缩数据流做字符串替换。这个规则是为本样本的初始化布局验证的，不能替代通用的多段 FLV 拼接、参数切换和时间戳重建逻辑。

## 6. 还原后的结构校验

剥离外层后，脚本从 FLV `DataOffset + 4` 开始逐标签检查：

- 标签类型必须是本样本使用的 8、9、18，分别为音频、视频、脚本数据。
- 标签头长度为 11 字节。
- 标签数据长度读取标签偏移 `1..3`，按大端解析。
- 标签结束后的 4 字节 `PreviousTagSize` 必须等于 `11 + DataSize`。
- 每个标签不能超出文件末尾。
- 必须精确遍历到文件结尾。

这属于结构和长度一致性校验，不是密码学完整性校验；即使标签长度合法，也仍需要实际解码检查媒体内容。

### 字节数核对

```text
原始文件                         51,539,596
减去固定头：46,310 × 15             694,650
减去重复 FLV 文件头及零标签长度           13
减去扩展头：1,057 × 11               11,627
-------------------------------------------
还原 FLV                         50,833,306 字节
```

这与实际输出文件大小一致。随后 MP4 大小不同，是容器索引、元数据和包表示方式不同所致。

## 7. 快速使用

### 7.1 环境

- Python 3：还原脚本只依赖标准库，无须 `pip install`。
- FFmpeg、ffprobe：用于媒体检查、转封装和解码验证。
- FFmpeg 需要能识别这个样本使用的 FLV HEVC 扩展；本机安装版本已验证可用，不承诺所有旧版本都支持。

将 `restore_slice.py` 放在当前目录。以下路径是示例，替换成自己的文件路径，路径有空格时保留引号。

### 7.2 还原 FLV

```sh
python3 restore_slice.py "input.slice" "restored.flv"
```

当前样本的预期统计输出：

```text
{'blocks': 46310, 'tags': 9621, 'extensions': {11: 1057}}
```

脚本完整解析并校验成功后才写出文件。使用 `xb` 模式创建输出文件，不会覆盖已有文件；目标目录需要事先存在。

### 7.3 转成普通 MP4

```sh
ffmpeg -n -i "restored.flv" \
  -map 0:v:0 -map "0:a:0?" \
  -c copy -tag:v hvc1 -movflags +faststart \
  "restored.mp4"
```

参数说明：

| 参数 | 作用 |
|---|---|
| `-n` | 输出存在时停止，避免覆盖 |
| `-map 0:v:0` | 选择第一个视频轨 |
| `-map "0:a:0?"` | 若存在，选择第一个音频轨 |
| `-c copy` | 音视频直接转封装，不重新编码 |
| `-tag:v hvc1` | 为该 HEVC 输出设置 MP4 视频标记；不改变编码算法 |
| `-movflags +faststart` | 将 MP4 索引移到文件前部，方便开始播放 |

该命令是针对本样本的 HEVC 视频，不应把 `-tag:v hvc1` 原样用于 H.264 或其他编码。

### 7.4 查看媒体信息与帧数

```sh
ffprobe -v error -count_frames \
  -show_entries stream=codec_name,profile,width,height,pix_fmt,avg_frame_rate,duration,nb_read_frames,sample_rate,channels:format=duration,size \
  -of json "restored.mp4"
```

`-count_frames` 会读取并解码媒体，耗时比仅查看文件头长。

### 7.5 完整解码验证

```sh
ffmpeg -v error -i "restored.mp4" \
  -map 0:v:0 -map 0:a:0 \
  -fps_mode passthrough -enc_time_base 1:1000 \
  -f null -
```

此命令用于验证当前有音频的视频样本，输出丢弃，不生成新视频。对无音频文件，移除音频 `-map` 或加 `?`。本样本运行后错误日志为空。

### 7.6 如果播放器不支持 HEVC

可另外生成 H.264/AAC 兼容版本：

```sh
ffmpeg -n -i "restored.mp4" \
  -map 0:v:0 -map "0:a:0?" \
  -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p \
  -c:a aac -b:a 128k -movflags +faststart \
  "compatible-h264.mp4"
```

这是可选的重新编码步骤，会有有损压缩，与前面的无重新编码转封装不同。本次交付的 `slice-restored.mp4` 使用直接转封装，没有运行这条兼容性转码命令。

## 8. 时间戳与时长陷阱

初步探测时，工具曾显示 `2098.494` 秒。这不能直接当成这个文件约 35 分钟长。

还原后的直播数据使用不从零开始的时间戳：

- 首个视频包 DTS 约为 1911.590 秒，包含 B 帧重排序时 DTS 不等于显示时间。
- 首个视频显示时间约为 1911.722 秒。
- 音频开始时间约为 1911.611 秒。
- 数据位于直播时间线靠后的位置，FLV 探测得到的持续时间可能受这些时间戳影响。

实际转封装后，媒体总时长为 187.048 秒，视频轨为 186.937 秒。判断直播片段长度应结合起始时间、结束时间、包时间戳与实际帧数，不能只看一个初步探测的 duration 值。

还原脚本本身不修改 FLV 时间戳。MP4 转封装由 FFmpeg 处理时间线；不要为了让数值看起来整齐，随意删除音视频之间原有的相对起始偏移。

## 9. 常见报错与处理

| 报错／现象 | 可能原因与处理 |
|---|---|
| 原始文件 `Invalid data found when processing input` | 文件开头是外层分片头，先还原，不是简单增加 probesize 就能解决 |
| `Packet mismatch` | 可能未去除后续分片头、重复 FLV 头或可选扩展头；也可能文件不完整 |
| `Concatenated FLV detected` | 初始化片段中的重复 FLV 文件头仍留在标签流中 |
| `Truncated header` | 末尾不足 15 字节，文件可能截断，或格式不符合当前假设 |
| `Invalid block length` | 块长度非法／超出文件；不要直接忽略后继续猜测边界 |
| `Missing extension length` / `Invalid extension length` | 扩展头不完整，或当前文件的扩展规则不同 |
| `Unexpected FLV header` | 重复初始化片段不是当前支持的 9 字节 FLV 头形式 |
| `No FLV header` | 输入不是该结构，或缺少开头初始化片段 |
| `FLV tag validation failed` | 外层拆分规则不匹配、分片缺失／乱序，或者数据损坏 |
| `FileExistsError` | 输出已经存在；换一个输出文件名 |
| MP4 有声音、没有画面 | 先检查播放器 HEVC 支持；若 FFmpeg 完整解码无误，可尝试兼容性转码 |

增加 `-probesize` 或 `-analyzeduration` 只能改善对有效媒体数据的探测，不会自动删除私有分片头。

## 10. 脚本的边界

当前工具有以下明确限制：

1. 只对这份样本完成了验证。没有覆盖其他快手版本、不同下载来源或其他平台同名后缀。
2. 假设固定头为 15 字节、块长为前两个字节的高 12 位，且字节 14 的最低位表示扩展存在。
3. 按文件中的原始顺序拼接；不恢复网络层缺包、不重排、不做分片去重。
4. 不验证或解释头中未确认字段，不根据疑似序号修复内容。
5. 只处理符合当前布局的重复 FLV 初始化头，不处理复杂的中途分辨率、编码配置或时间基变化。
6. 只接受本样本中出现的 FLV 标签类型 8、9、18。其他合法扩展标签也会被当前严格校验拒绝。
7. 文件需要有足够的初始化信息。仅有中途媒体片段时，可能缺失 HEVC 参数集或 AAC 配置，不能凭空恢复。
8. 整个输入及输出会读入内存，峰值占用高于单个文件大小。超大文件适合改成流式解析，并在临时文件中做最终校验。
9. 输出目录必须已存在。解析失败时不输出“修复了一部分”的文件。
10. 脚本没有判断加密媒体的能力；本样本可以直接拆包并正常解码，不代表其他样本也没有额外保护或编码层。

若另一个文件失败，应先记录失败偏移、块头、长度、剩余字节数，再与其格式比对，而不是关闭所有校验强行生成 MP4。

## 11. 已确认与未确认的内容

### 已确认

- 整个样本可按上述块长规则完整遍历。
- 固定头与扩展头剥离后，可得到完整 FLV 字节流。
- 两份开头初始化片段可按上述方式合并。
- 所有 9,621 个标签的长度、类型和 PreviousTagSize 都通过校验。
- 标准 FFmpeg 可识别 HEVC/AAC，直接转封装为 MP4。
- 全部音视频解码检查无报错。
- 配套脚本重新输出的 FLV，与分析过程中还原的 FLV 逐字节一致。

### 未确认

- 外层协议的官方名称、版本号和完整字段定义。
- 低 4 位值 0、2、3 的正式含义。
- 固定头其他字节的序号、时间、标志等具体划分。
- 扩展头内容的正式类型与字段含义。
- 其他版本、其他编码或丢包、乱序、截断文件的处理规则。

本 README 中的“分片头”“扩展头”是描述观察到的结构所用的名称，不宣称对应官方协议术语。
